# المتطلبات غير الوظيفية (Non-Functional Requirements)

توثيق تفصيلي للمعايير غير الوظيفية للنظام وتشمل: الأداء، الأمان، سلامة ودقة البيانات المالية، التوافق وتجربة المستخدم، قابلية التتبع، والنسخ الاحتياطي واستمرارية العمل.

---

## 1. الأداء والسرعة (Performance & Speed)

| المعيار | الهدف التشغيلي والتقني | آلية التطبيق البرمجية |
| :--- | :--- | :--- |
| **سرعة البحث اللحظي** | زمن استجابة للبحث عن الأصناف والعملاء أقل من **150ms**. | استخدام تقنية Livewire مع خاصية `wire:model.live.debounce.300ms` وفهارس قاعدة البيانات (Indexes) على أعمدة `code`, `name`, `phone`. |
| **سرعة إصدار الفاتورة** | حفظ واعتماد الفاتورة وتحديث المخزون والقيود المالية في أقل من **500ms**. | تنفيذ العمليات عبر `DB::transaction()` خفيفة ومركزة وتجنب العمليات الحلقية (N+1 Queries) باستخدام `with(['customer', 'items'])` Eager Loading. |
| **خفة تحميل الواجهة** | سرعة تنقل فائقة بين الصفحات تشبه تطبيقات الصفحة الواحدة (SPA). | استخدام خاصية `wire:navigate` في الروابط لتحميل محتوى الصفحات في الخلفية، وتقليل أحجام أصول الـ CSS والـ JS عبر Vite Bundler. |
| **كفاءة استهلاك الذاكرة** | استهلاك منخفض لذاكرة السيرفر حتى مع زيادة العمليات اليومية. | استخدام تقنيات التصفح المجزأ (Pagination) في الجداول وكشوف الحسابات وتجنب استدعاء مجموعات بيانات كاملة بدون تحديد. |

## 2. الأمان وحماية البيانات (Security & Access Control)

| المعيار | الهدف والمستوى المطلوب | آلية التطبيق |
| :--- | :--- | :--- |
| **التحكم في الوصول والصلاحيات** | منع أي مستخدم من الوصول لوظيفة أو شاشة غير مصرح له بها. | تطبيق حزمة **Spatie Laravel Permission** واستخدام Middleware مثل `role_or_permission` على مستوى الـ Routes و Livewire Authorization checks. |
| **حماية المعاملات من التضارب (Race Conditions)** | منع بيع الصنف مرتين إذا حاول مستخدمان اعتماده في نفس اللحظة. | تطبيق القفل السطري **Row-level Locking** باستخدام `lockForUpdate()` في استعلام قراءة وتحديث رصيد الصنف داخل Transaction. |
| **حماية النماذج والتنقل** | منع هجمات CSRF، والتلاعب بالمدخلات XSS و SQL Injection. | التشفير التلقائي لـ Tokens في Livewire 4، واستخدام Eloquent ORM المعقم والمجهز بـ Prepared Statements، وتمرير الـ Validation Rules الصارمة. |
| **أمان الجلسات وكلمات المرور** | تأمين حسابات الدخول وسرية كلمات المرور. | استخدام خوارزمية التشفير القياسية `Bcrypt / Argon2id` عبر Laravel Breeze مع دعم إنهاء الجلسات عند الخمول (Session Timeout). |

## 3. دقة البيانات المالية والمخزنية (Financial & Decimal Precision)

| المعيار | المتطلب الصارم | التفاصيل وقواعد التطبيق |
| :--- | :--- | :--- |
| **نوع البيانات الإلزامي** | منع استخدام `FLOAT` أو `DOUBLE` نهائيًا في النظام. | يجب أن تكون كافة الأعمدة المالية وأعمدة الكميات والأوزان من نوع **`DECIMAL(12,3)`** في جميع ملفات الـ Migrations ونماذج الـ Eloquent. |
| **تغطية الدقة الرقمية** | تطبيق الدقة الثلاثية على كافة المتغيرات الحسابية. | يشمل: أسعار التكلفة (Cost Price)، أسعار البيع (Selling Price)، الكميات (Quantity)، الأوزان (Weight)، مبالغ الخصومات (Discounts)، المدفوعات (Payments)، الرصيد المتبقي (Remaining)، الأرباح (Profits)، وأرصدة العملاء والموردين. |
| **تجنب أخطاء التقريب** | منع أي فروقات محاسبية في المجاميع التراكمية. | استخدام دوال الحساب الدقيقة في PHP وقاعدة البيانات (مثل دوال `bcmath` أو العمليات المباشرة على الأعداد العشرية) لضمان تطابق الإجمالي الفرعي والخصومات مع الصافي النهائي. |

## 4. التوافق وسهولة الاستخدام (Compatibility, RTL & Accessibility)

| المعيار | المواصفات الفنية | التطبيق العملي |
| :--- | :--- | :--- |
| **التصميم المتجاوب (RWD)** | تجربة استخدام متكاملة على شاشات الموبايل، التابلت، والكمبيوتر. | تصميم معتمد على منهجية **Mobile First** باستخدام Tailwind CSS و Flowbite Responsive Breakpoints (`sm`, `md`, `lg`, `xl`). |
| **دعم كامل للغة العربية (RTL)** | دعم اتجاه القراءة من اليمين لليسار في كافة المكونات والنصوص. | ضبط `dir="rtl"` في الهيكل الأساسي للـ HTML مع استخدام فئات Tailwind الموجهة منطقيًا (`ps-`, `pe-`, `start-`, `end-`) ومراعاة اتجاه الأيقونات والجداول. |
| **دعم الوضعين المظلم والفاتح** | راحة للعين أثناء الاستخدام في مختلف بيئات العمل الميدانية والمكتبية. | دعم كامل لـ **Dark Mode / Light Mode** مدمج في الـ Layout ومحدد بالفئات الخاصة بـ Flowbite مع حفظ تفضيل المستخدم في التخزين المحلي. |
| **سهولة إدخال الكاشير (POS Friendly)** | إمكانية إصدار الفواتير بالاعتماد الكامل على لوحة المفاتيح وقارئ الباركود. | تركيز تلقائي للمؤشر (Autofocus) على حقل البحث، دعم اختصارات لوحة المفاتيح لإضافة الأسطر وحفظ الفاتورة، وأزرار لمس كبيرة للموبايل (44px-48px). |

## 5. قابلية التتبع والمساءلة (Auditability & Traceability)

| المعيار | المتطلب | آلية التطبيق |
| :--- | :--- | :--- |
| **سجل التدقيق الشامل (Audit Log)** | توثيق جميع العمليات الحساسة في جدول مخصص ومحمي من الحذف. | تسجيل العمليات: إضافة/تعديل/إلغاء فاتورة بيع، فواتير الشراء، المرتجعات، سندات القبض، تعديلات المخزون، وتغييرات الصلاحيات. |
| **تفاصيل بيانات السجل** | توفير بيانات غير قابلة للإنكار للمساءلة الإدارية. | تخزين: معرف المستخدم (`user_id`)، نوع الحدث (`action_type`)، اسم الموديل المتأثر (`auditable_type`, `auditable_id`)، القيم القديمة (`old_values` بتنسيق JSON)، القيم الجديدة (`new_values`)، وعنوان IP والتاريخ والوقت بدقة الثواني. |
| **منع الحذف الفعلي للبيانات الحساسة** | حظر الحذف الفيزيائي (Permanent Deletion) للفواتير والحركات المالية. | الاعتماد على الحالات التشغيلية (مثل `Cancelled`, `Inactive`, `Draft`) لضمان عدم وجود فجوات في تسلسل أرقام الفواتير ومطابقة الحسابات المالية القديمة. |

## 6. الموثوقية والنسخ الاحتياطي (Reliability, Backup & Disaster Recovery)

| المعيار | المتطلب | خطة التنفيذ |
| :--- | :--- | :--- |
| **النسخ الاحتياطي الدوري** | ضمان عدم فقدان البيانات تحت أي ظرف تقني أو فشل في الهاردوير. | جدولة تشغيل نسخ احتياطي آلي لقاعدة البيانات بشكل يومي، مع تسجيل تاريخ وحجم آخر نسخة وتوفير إمكانية أخذ نسخة فورية بضغطة زر للمدير. |
| **تعدد مواقع الحفظ** | الاحتفاظ بنسخ خارج خادم الإنتاج (Offsite Storage). | تصدير ملفات الـ SQL المضغوطة وحفظ نسخ محلية مع إمكانية الرفع إلى وحدة تخزين سحابية آمنة (مثل S3 أو مساحة تخزين منفصلة). |
| **اختبار الاستعادة (Restore Test)** | سهولة وسرعة استعادة البيانات عند الطوارئ. | كتابة وتوثيق أوامر الاسترجاع المباشرة عبر أداة سطر الأوامر (CLI Scripts) لتقليل وقت التعطل (RTO - Recovery Time Objective) لأقل من 15 دقيقة. |

## 7. استمرارية العمل وتطبيق الويب التقدمي (PWA & Offline Strategy)

| المعيار | المتطلب | القواعد الصارمة |
| :--- | :--- | :--- |
| **تثبيت التطبيق (PWA Installable)** | تثبيت النظام كتطبيق أصلي على شاشات أجهزة Android والكمبيوتر. | توفير ملف `manifest.json`، وأيقونات بأحجام قياسية (192x192 و 512x512)، و Service Worker مخصص لتسجيل التطبيق وإظهار واجهة التثبيت. |
| **حدود العمل دون إنترنت (Offline Constraints)** | الحفاظ على اتساق المخزون وتفادي العمليات المتضاربة. | يُسمح بتخزين الواجهة الثابتة (Static UI Shell) والأصول في الكاش؛ **بينما تُحظر العمليات الحساسة (البيع، الشراء، الصرف المخزني، سندات القبض) عند انقطاع الإنترنت** وتتطلب اتصالاً مباشرًا بالخادم لحماية الأرصدة ومنع العجز المخزني. |
