> **نظام إدارة الفواتير والمخزون والمبيعات — سرور كوفي ERP**  
> **الإصدار:** 1.0  
> **بيئة الاختبار:** Python 3.13 + Playwright + Pytest + Laravel Monolith (Livewire 4 + Alpine.js)

## 🎯 1. نظرة عامة على معمارية الاختبارات (Testing Architecture)

تم بناء منظومة الاختبارات التفاعلية بنظام **End-to-End (E2E)** لمحاكاة حركة المستخدم الحقيقي على المتصفح بالكامل، وتتميز المعمارية بالخصائص التالية:

1. **قاعدة بيانات منعزلة تماماً (`database/e2e_testing.sqlite`):**
   - لا تلمس قاعدة بيانات العمل الأساسية نهائياً.
   - يتم تصفيرها وإعادة بنائها تلقائياً (`migrate:fresh --seed`) مع كل تشغيل لاختبار حالة النظام من الصفر (Clean State).
   - يتم زرع المستخدمين الأساسيين (Super Admin) والمخزن الرئيسي فقط، بينما يتم إنشاء الفروع والأصناف والعملاء تفاعلياً بواسطة المتصفح.

2. **جلسة متصفح مستمرة ونافذة واحدة (Persistent Single Window):**
   - المتصفح يفتح نافذة واحدة ويسجل الدخول مرة واحدة فقط في البداية.
   - يتم تنفيذ جميع الاختبارات بتسلسل منطقي داخل نفس النافذة دون فتح وإغلاق متكرر، مع فاصل زمني (1.5 ثانية) لسهولة المتابعة البصرية.

3. **التعامل الذكي مع Livewire و Dialogs:**
   - انتظار شبكة الـ AJAX (`networkidle`) لضمان استقرار المكونات التفاعلية.
   - اعتماد رسائل التأكيد المنبثقة (`wire:confirm`) تلقائياً وبشكل موحد.
   - دعم التوافق مع الشاشات المتجاوبة واستهداف الأزرار المرئية على سطح المكتب (`1280x800`).

## 🚀 2. دليل أوامر التشغيل السريع (Commands Cheat Sheet)

### أ. التشغيل المرئي التفاعلي (المتصفح يفتح أمامك):
```bash
# تشغيل السيناريوهات الأساسية (1 إلى 4) مرئياً:
python run_all_tests.py --headed

# تشغيل اختبار معين بمفرده (مثال: الفروع والمخازن):
python run_all_tests.py --headed --test stores

# تشغيل كافة السيناريوهات العشرة بالكامل:
python run_all_tests.py --headed --all
```

### ب. التشغيل السريع في الخلفية (Headless):
```bash
# تشغيل سريع في الخلفية بدون فتح نافذة المتصفح:
python run_all_tests.py --e2e

# تشغيل اختبار معين في الخلفية:
python run_all_tests.py --test items
```

### السيناريو 1: الحسابات والتنقل (`test_01_auth_and_navigation.py`)

* **الهدف:** التأكد من صفحة الدخول، كتابة رقم الهاتف وكلمة المرور، والتحويل للوحة التحكم.
* **الخطوات:**
  1. التوجه إلى `/login`.
  2. التأكد من وجود حقل الهاتف `#phone` وكلمة المرور `#password`.
  3. ملء بيانات المدير العام (`01012316954` / `password`).
  4. الضغط على زر الدخول والانتظار حتى الانتقال للرئيسية `/`.
  5. التأكد من ظهور اسم النظام "سرور كوفي" وشريط الإدارة.

#### 1.2 `test_admin_dashboard_overview` (لوحة التحكم الرئيسية)
* **الهدف:** التأكد من عرض ملخص المبيعات، مبدل الفروع، والإحصائيات السريعة.
* **الخطوات:**
  1. زيارة الصفحة الرئيسية `/`.
  2. التحقق من خلو الصفحة من أخطاء 500.
  3. التأكد من وجود هيدر النظام ومحدد الفرع النشط.

#### 1.3 `test_sidebar_navigation_links` (فحص سلامة الروابط الجانبية)
* **الهدف:** فحص 12 رابط أساسي في القائمة الجانبية والتأكد من فتح كل صفحة بنجاح بدون أخطاء السيرفر.

  1. `/invoices` (سجل فواتير المبيعات)
  2. `/invoices/create` (كاشير ومبيعات)
  3. `/items` (الأصناف والمخزون)

  6. `/purchases` (فواتير المشتريات)

## 🛡️ 4. الضمانات التقنية المطبقة في الاختبارات (Rules & Compliance)

| القاعدة التقنية | كيفية التحقق منها في الاختبارات |
|---|---|
| **`DECIMAL(12,3)`** | كافة الكميات والأوزان تُدخل وتُفحص بـ 3 خانات عشرية (مثل `15.000`, `0.250`). |
| **`lockForUpdate()`** | يتم اختبار البيع والشراء والتحويل داخل DB Transactions لمنع البيع المزدوج. |
| **عدم الحذف الفيزيائي** | جميع عمليات الحذف هي Soft Deletes وتُنقل لسلة المحذوفات مع إمكانية الاسترجاع 100%. |
| **التوافق مع العربية RTL** | يتم الفحص بلغة عربية ونصوص أصلية بدون كسر التنسيق أو اتجاه الصفحة. |
| **العزل التام للبيانات** | سيرفر الاختبار يعمل بـ `APP_ENV=testing` و `.env.e2e` المنعزلة تماماً عن بيانات الإنتاج. |
