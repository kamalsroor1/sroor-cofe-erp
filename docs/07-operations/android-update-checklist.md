# قائمة فحص يدوية لتحديث Android داخل التطبيق على جهاز حقيقي (APP-3)

نفّذ هذه القائمة على **جهاز Android حقيقي** (ليس emulator) قبل كل إصدار APK.
اختبارات الـ unit (`cd backend && node --test scripts/app-update/appUpdate.test.mjs`) بتغطي منطق الـ JS بس. التنزيل وحساب الـ hash وفحص التوقيع وشاشة التثبيت مفيش طريقة تتأكد منها غير على جهاز.

## طريقة العمل

1. `GET /api/v1/app/check-update?platform=android&version_code=<build المثبّت>` بيرجّع `download_url` و`checksum` (SHA-256 من `app_versions.apk_checksum`) و`file_size_bytes` و`force_update`.
2. `useAppUpdate` ← `createAppUpdater` بيبعت الرابط والـ checksum لـ Capacitor plugin اسمه `AppUpdater` (`android/app/src/main/java/com/sroor/cofe/erp/AppUpdaterPlugin.java`).
   - لو الـ plugin مش موجود (`Capacitor.isPluginAvailable('AppUpdater')` = false، يعني APK قديم بيحمّل الـ JS من السيرفر)، الـ JS بيعمل navigate لرابط الـ APK علشان الـ DownloadListener القديم في النسخة دي ينزّله ويثبّته، وبيعرض رسالة `error_updater_unavailable`.
3. الـ plugin بينزّل الـ APK في `cacheDir/app-updates/` ويبعت البايتات الفعلية في event اسمه `downloadProgress`. وبيحسب الـ SHA-256 أثناء التنزيل، فلو مش مطابق بيرفض التثبيت. بعدها بيتأكد إن اسم الـ package وشهادة التوقيع مطابقين للتطبيق المثبّت، وبعدين يفتح شاشة تثبيت النظام عن طريق الـ FileProvider.
4. أكواد الأخطاء (`CHECKSUM_MISMATCH`، `SIGNATURE_MISMATCH`، `PACKAGE_MISMATCH`، `INSTALL_PERMISSION_REQUIRED`…) بتظهر للمستخدم كرسائل مترجمة (`lang/*/app_update.php`، المفاتيح `error_*`).
5. منع الـ loop: الفحص التلقائي بيتعمل مرة واحدة بس في كل جلسة لنفس الـ build المثبّت (`sessionStorage` بالمفتاح `app_update_checked:<platform>:<build>`). التطبيق عمره ما بيزوّر رقم الإصدار ولا بيعمل reload لنفسه. التحديث الإجباري بيتحفظ في نفس الجلسة، فالـ reload مش بيفك القفل. ولو المستخدم أجّل تحديث اختياري، مش هيظهر له تاني تلقائيًا لنفس الإصدار.

## المتطلبات

- نسختين release موقّعين بنفس الـ keystore: الإصدار N (مثبّت على الجهاز) والإصدار N+1. الإصدار N+1 بيترفع من super-admin ← إصدارات التطبيق، والسيرفر بيحسب الـ SHA-256 وقت الرفع.
- نسخة N+1 تانية موقّعة بمفتاح مختلف (الـ debug keystore ينفع)، علشان اختبار التوقيع.
- لغة الجهاز عربي في جولة وإنجليزي في جولة. وجرّب الوضع الداكن مرة والفاتح مرة.

## القائمة

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| 1 | ثبّت N وسجّل دخول. انشر N+1 (اختياري). افتح التطبيق تاني | نافذة التحديث تظهر مرة واحدة، وفيها الحجم والتاريخ والملاحظات اللي جاية من الـ API |
| 2 | اضغط «تذكيري لاحقاً»، واقفل التطبيق خالص وافتحه تاني | النافذة مش بتظهر لنفس N+1. ولما تضغط «فحص التحديثات» من الإعدادات بتظهر تاني |
| 3 | اضغط «تحديث وتثبيت الآن» على شبكة بطيئة | النسبة المئوية حقيقية، ويظهر «تم تنزيل x من y ميجابايت»، وفي الآخر تظهر مرحلة «التحقق» |
| 4 | أول مرة وصلاحية «تثبيت التطبيقات غير المعروفة» مقفولة | شاشة إعدادات النظام الخاصة بالتطبيق بتتفتح، والنافذة بتعرض رسالة الصلاحية مترجمة. وبعد ما تسمح، «إعادة المحاولة» بتكمّل |
| 5 | كمّل التثبيت | شاشة التثبيت بتتفتح. بعد التثبيت التطبيق يفتح على N+1 ومفيش نافذة تحديث |
| 6 | الغِ رسالة النظام الأولى، واضغط «فتح شاشة التثبيت مرة أخرى» | شاشة التثبيت بتتفتح من غير ما الملف يتنزّل تاني (الملف بيتعاد حساب الـ hash بتاعه وبيُستخدم تاني) |
| 7 | **checksum غلط**: حط قيمة `apk_checksum` غلط لـ N+1 في قاعدة بيانات الاختبار (أو بدّل الملف على القرص بعد الرفع) | التنزيل بيخلص، وبعدها التثبيت بيترفض برسالة الـ checksum مترجمة، وشاشة تثبيت النظام مش بتتفتح |
| 8 | **توقيع مختلف**: انشر نسخة N+1 الموقّعة بمفتاح تاني | التثبيت بيترفض برسالة التوقيع مترجمة، وشاشة تثبيت النظام مش بتتفتح |
| 9 | **تحديث إجباري**: علّم N+1 كـ `is_force_update` وافتح التطبيق تاني | النافذة مستحيل تتقفل (مفيش X ولا Esc ولا ضغط على الخلفية ولا «لاحقاً»). لو عملت reload أو فتحت التطبيق تاني في نفس الجلسة، طلب الفحص **مش** بيتبعت تاني (اتأكد من logs السيرفر)، **لكن النافذة الإجبارية بترجع تظهر تاني** (بتتسترجع من `sessionStorage` بالمفتاح `app_update_forced:<platform>:<build>`) والتطبيق يفضل مقفول. ولو قفلت التطبيق خالص (جلسة جديدة)، الفحص بيتعمل مرة واحدة كمان |
| 10 | تحديث إجباري، والغِ شاشة تثبيت النظام | مفيش حاجة تتعمل في التطبيق غير من النافذة. مفيش reload loop ولا طلبات بتتكرر |
| 11 | شغّل وضع الطيران أثناء التنزيل | تظهر رسالة فشل التنزيل مترجمة، و«إعادة المحاولة» بتشتغل بعد ما النت يرجع |
| 12 | `download_url` مش موجود، أو رابط http في نسخة release | تظهر رسالة «رابط التحميل غير متاح» مترجمة، ومفيش أي حاجة بتتنزل |
| 13 | عربي + إنجليزي، داكن + فاتح، موبايل 360px وتابلت | النصوص مترجمة، والاتجاه RTL/LTR مظبوط، والأزرار ≥ 44px |
| 14 | **أول rollout لأجهزة من غير plugin**: ثبّت نسخة الـ APK الحالية اللي على الإنتاج (اللي قبل `AppUpdater`، مثلًا versionCode 3 / 1.0.2)، وانشر بعد كده تحديث إجباري (`is_force_update`) للنسخة الجديدة، وبعدين اضغط «تحديث وتثبيت الآن» | النافذة الإجبارية بتظهر. الضغط بيسلّم رابط الـ APK للـ DownloadListener القديم في النسخة دي، فالتنزيل بيبدأ (إشعار نظام) وشاشة التثبيت بتتفتح، والنافذة بتعرض رسالة «التحديث داخل التطبيق غير متاح» مترجمة مع «إعادة المحاولة». الجهاز **لازم** يوصل للـ APK الجديد ويثبّته. مفيش رسالة «تأكد من الإنترنت» مضللة |

## ملاحظات

- Android نفسه بيرفض أي تحديث موقّع بمفتاح مختلف. فحص التوقيع جوه التطبيق وظيفته بس إنه يحط رسالة واضحة مكان فشل النظام الصامت.
- روابط التحديث اللي بتبدأ بـ http مقبولة بس في النسخ الـ debuggable (الـ harness المحلي). نسخ الـ release لازم تستخدم https.
- التحديث الحقيقي لـ Windows (Electron) هو مهمة APP-7. لحد ما تخلص، مسار الديسكتوب بيستخدم الـ bridge الموجود `electronAPI.updater`، ولو مش موجود بتظهر رسالة خطأ مترجمة. التقدم الوهمي اتشال.
