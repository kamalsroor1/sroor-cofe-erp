# قوائم فحص يدوية: تحديث Android وWindows ودرج الكاش (W2 batch 5 — APP-3 امتداد، APP-7، APP-5 امتداد)

القوائم دي بتكمّل `android-update-checklist.md` و`desktop-print-drawer-checklist.md`، وفيها السلوك الجديد بس.
اختبارات الـ unit بتغطي منطق القرار:

- SPA: `cd backend && node --test tests/js/appUpdater.test.js` (أو `npm run test:js`).
- Desktop: `cd desktop && npm test` (`versionCode`، `authenticode`، `updateState`، `updater`، `drawerKick`، `settingsSanitizer`).

التنزيل الفعلي وحساب الـ hash وشاشة التثبيت وتشغيل الـ installer وفتح الدرج مفيش طريقة تتأكد منها غير على جهاز حقيقي.

## السلوك الجديد باختصار

| الموضوع | السلوك |
|---|---|
| الـ checksum | إجباري. إصدار من غير SHA-256 صالح عمره ما بيتثبّت، ومينفعش يبقى «إجباري» (عشان مايقفلش البرنامج على تحديث مستحيل) |
| التحديث الاختياري | بيظهر **مرة واحدة في كل فتح للتطبيق**. «ذكّرني لاحقًا» بيخفيه لحد الفتحة الجاية بس، ومفيش تأجيل دائم (المفتاح القديم `app_update_dismissed:*` بيتمسح) |
| التحديث الإجباري | النافذة مالهاش زرار قفل، ومش بتتقفل بـ Esc أو بالضغط برّه، والـ reload مش بيفكها، والسيرفر مش بيتسأل تاني في نفس الفتحة |
| APK قديم من غير plugin `AppUpdater` | التثبيت بيترفض (مش بيتبعت رابط الـ APK للـ WebView)، ويظهر زرار «التحميل اليدوي» اللي بيفتح `/download` |
| `SIGNATURE_UNVERIFIABLE` | رسالة `app_update.error_signature_unverifiable` + زرار «التحميل اليدوي» |
| `SIGNATURE_MISMATCH` | رفض نهائي + «كلم الدعم الفني»، من غير زرار تحميل |
| صفحة `/download` | عامة (من غير login)، فيها آخر إصدار Android وWindows ببصمة SHA-256 وأمر التحقق. نافذة التحديث مش بتغطيها حتى لو فيه تحديث إجباري |
| Desktop `version_code` | `SemverCode(app.getVersion())` (مثلًا 1.2.3 = 1002003)، بدل `'0'` |
| Desktop التحقق | SHA-256 + الحجم بالظبط (من `file_size_bytes`) + Authenticode (السياسة مقفولة لحد شراء الشهادة؛ التوقيع المكسور `HashMismatch` بيترفض دايمًا) |
| Desktop منع الـ loop | 3 محاولات فاشلة خلال 24 ساعة ← `app_update.error_update_attempts_exhausted` وصفحة التحميل بتتفتح في المتصفح |
| Desktop rollback | لو الإصدار الجديد فشل يكمّل تشغيل (60 ثانية بعد تحميل الصفحة) 3 مرات ← رسالة نظام **بتعرض** الرجوع للإصدار السابق (`rollback` من الـ API)، بنفس التحقق، ومفيش رجوع صامت |
| درج الكاش | pin 2 (افتراضي) أو pin 5، إعداد لكل جهاز في إعدادات الديسكتوب، وزرار التجربة بيعرض النتيجة الحقيقية |

## 1. Android (جهاز حقيقي، Android 9 وAndroid 12 على الأقل)

المتطلبات: إصدار N مثبّت، وN+1 موقّع بنفس الـ keystore، وN+1 تاني موقّع بمفتاح مختلف، وAPK قديم من غير plugin `AppUpdater`.

| # | الخطوة | النتيجة المتوقعة | تم |
|---|---|---|---|
| A1 | انشر N+1 اختياري، وافتح التطبيق | النافذة تظهر مرة واحدة | ☐ |
| A2 | اضغط «ذكّرني لاحقًا»، واعمل reload أو روح لصفحة تانية | النافذة مش بتظهر تاني في نفس الفتحة | ☐ |
| A3 | اقفل التطبيق خالص (من الـ recent apps) وافتحه تاني | النافذة **بتظهر تاني** (مرة في كل فتح) | ☐ |
| A4 | خلّي N+1 إجباري وافتح التطبيق | مفيش زرار قفل؛ زرار الرجوع وEsc والضغط برّه مش بيقفلوها؛ الـ reload بيرجّعها من غير طلب جديد للسيرفر | ☐ |
| A5 | امسح الـ checksum من الإصدار في قاعدة بيانات تجريبية (مش production) وخليه إجباري | النافذة تظهر كاختيارية، و«تحديث» بيرفض برسالة `error_missing_checksum` | ☐ |
| A6 | ثبّت N+1 الموقّع بمفتاح مختلف | رسالة `error_signature_mismatch` (رفض + الدعم الفني)، ومفيش زرار «التحميل اليدوي» | ☐ |
| A7 | جهاز مابيقدرش يقرا التوقيع (أو APK تالف التوقيع) | رسالة `error_signature_unverifiable` + زرار «التحميل اليدوي» بيفتح `/download` | ☐ |
| A8 | APK قديم من غير plugin، وتحديث إجباري | «تحديث» بيدّي `error_updater_unavailable` + زرار «التحميل اليدوي»؛ مفيش تنزيل APK من غير تحقق | ☐ |
| A9 | من `/download` على نفس الجهاز | الصفحة تفتح من غير login، والنافذة الإجبارية مش مغطياها، وكارت Android عليه «جهازك»، والبصمة تتنسخ، والتحميل يشتغل | ☐ |
| A10 | كرر A1 وA6 وA9 بالإنجليزي، وفي الوضع الداكن والفاتح | كل النصوص مترجمة، والاتجاه صح (RTL/LTR) | ☐ |

## 2. Windows (جهاز Windows نظيف)

المتطلبات: installer لإصدار N (مثلًا 1.0.0) وN+1 (1.1.0) مرفوعين من super-admin بكود = SemverCode، وإصدار N+1 تاني ملفه متعدّل بايت واحد بعد الرفع (لاختبار الـ checksum).

| # | الخطوة | النتيجة المتوقعة | تم |
|---|---|---|---|
| W1 | ثبّت N وافتحه، وراقب طلب `check-update` (لوج السيرفر) | `version_code=1000000` مش `0` | ☐ |
| W2 | انشر N+1 واضغط «تحديث» | تقدم حقيقي، ثم «جاري التحقق»، ثم معالج NSIS ظاهر (مش صامت)، والبرنامج يقفل | ☐ |
| W3 | بعد التثبيت افتح البرنامج | يفتح على N+1، ومفيش نافذة تحديث، و`updater:get-state` (من DevTools: `await electronAPI.updater.getState()`) فيه `lastResult.status = success` | ☐ |
| W4 | اضغط «تحديث» وإنت على آخر إصدار (أو السيرفر رجّع نفس الكود) | رسالة «إنت على آخر إصدار»، والنافذة تتقفل، ومفيش loop | ☐ |
| W5 | الملف المتعدّل (checksum مختلف) | رفض برسالة `error_checksum_mismatch`، والملف المؤقت يتمسح | ☐ |
| W6 | `file_size_bytes` غلط في قاعدة بيانات تجريبية | رفض برسالة `error_size_mismatch` | ☐ |
| W7 | كرر الفشل 3 مرات في نفس اليوم | التالتة: `error_update_attempts_exhausted` وصفحة `/download` تتفتح في المتصفح الافتراضي؛ أي محاولة بعدها في نفس الـ 24 ساعة نفس النتيجة من غير تنزيل | ☐ |
| W8 | ألغِ معالج NSIS في النص، وافتح N تاني | المحاولة تتحسب فاشلة (`lastResult.status = failed`) | ☐ |
| W9 | محاكاة crash: افتح N+1 واقفله بـ Task Manager قبل 60 ثانية، 4 مرات متتالية | في الفتحة الرابعة تظهر رسالة نظام بتعرض الرجوع لـ N (لو السيرفر بيرجّع `rollback`)؛ «الاستمرار» مايعملش حاجة؛ «تثبيت السابق» بيمر بنفس التحقق | ☐ |
| W10 | افتح N+1 وسيبه أكتر من 60 ثانية، وبعدها اقفله عادي | مفيش عرض rollback بعد كده (`watchingUpdate = false`) | ☐ |
| W11 | Authenticode: سيب `requireAuthenticode = false` | installer مش موقّع بيتثبّت؛ installer موقّع وملفه متعدّل (`HashMismatch`) بيترفض بـ `error_installer_signature` | ☐ |
| W12 | (بعد شراء الشهادة) فعّل `requireAuthenticode` وحط الـ thumbprint في `src/config/updatePolicy.js` | الموقّع من الناشر ده بس بيعدي؛ غير الموقّع أو ناشر تاني بيترفض | ☐ |
| W13 | DevTools ← `updater:error` و`downloadAndInstall()` | الـ renderer بياخد أكواد `app_update.*` بس؛ مفيش مسارات ملفات ولا روابط ولا رسائل exception | ☐ |

## 3. درج الكاش (Windows + طابعة حرارية + درج على منفذ DK)

| # | الخطوة | النتيجة المتوقعة | تم |
|---|---|---|---|
| D1 | إعدادات الأجهزة ← اختار الطابعة وسيب pin 2 ← «تجربة الدرج» | الدرج يفتح، والرسالة «أمر الفتح (pin 2) اتبعت…» | ☐ |
| D2 | درج متوصل على pin 5: اختار pin 5 ← «تجربة الدرج» | الرسالة «اتحفظ pin 5»، والدرج يفتح (البايتات `1B 70 01 19 FA`) | ☐ |
| D3 | اقفل البرنامج وافتحه | الاختيار محفوظ على الجهاز ده بس (ملف `sroor-desktop-config.json`)، وجهاز تاني على نفس المحل مش متأثر | ☐ |
| D4 | بيع كاش من POS | الدرج يفتح على الـ pin المختار من غير restart | ☐ |
| D5 | افصل الطابعة واضغط «تجربة الدرج» | رسالة خطأ حقيقية (`printer_not_found` / `drawer_failed`) بدل «تم إرسال الإشارة» | ☐ |
| D6 | طابعة بترفض RAW | الرسالة بتقول إن الإشارة اتبعتت عن طريق التعريف | ☐ |
| D7 | من DevTools: `electronAPI.saveSettings({ cashDrawerPin: 3 })` و`'5'` | الاتنين بيرجعوا `invalid_settings` ومفيش حاجة بتتحفظ | ☐ |

## 4. لوحة المنصة (super-admin)

| # | الخطوة | النتيجة المتوقعة | تم |
|---|---|---|---|
| S1 | «حذف» مستأجر نشط | رسالة «أوقف المستأجر أو ألغيه الأول»، ومفيش طلب | ☐ |
| S2 | مستأجر موقوف ← «حذف» ← اكتب كود غلط | الزرار مايكمّلش، ورسالة «الكود مش مطابق» | ☐ |
| S3 | اكتب الكود صح | لو الـ 2FA قديم: نافذة step-up ثم الطلب يتعاد مرة واحدة؛ النتيجة 202 ورسالة «تم طلب الأرشفة»؛ صفحة المستأجر بتتحدّث كل 10 ثواني لحد ما الحالة تخلص | ☐ |
| S4 | اطلب الأرشفة تاني وهي شغالة | 409 بعنوان «الأرشفة شغالة بالفعل» ونص السيرفر المترجم | ☐ |
| S5 | ألغِ نافذة الـ step-up | رسالة «تم إلغاء التأكيد»، ومفيش طلب | ☐ |
| S6 | رفع إصدار: Windows باسم 1.2.3 | التلميح تحت كود الإصدار بيقول 1002003؛ الملف بيقبل `.exe` بس؛ مفيش iOS؛ أخطاء الـ 422 بتظهر تحت كل حقل (بعد ربط `errors` في الـ view، شوف تقرير الـ lane) | ☐ |
