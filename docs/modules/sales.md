# 🧾 موديول إدارة المبيعات والفواتير والعملاء (Sales & Invoicing Module)

## 1. نبذة عن الموديول:
موديول المبيعات هو السجل المحاسبي المركزي لكافة العمليات المالية الصادرة، يوثق كافة الفواتير النقدية والآجلة والمدفوعة جزئياً، وينظم حسابات ومديونيات العملاء، ويدير عمليات الإلغاء والمرتجعات الضريبية مع الحفاظ على تسلسل الدفاتر المالية وعكس حركات المخزون آلياً.

---

## 2. صفحات وشاشات الموديول:
* **[سجل فواتير المبيعات (Invoices)](../pages/invoices.md):** استعراض وأرشفة والبحث في فواتير المبيعات وإلغاء الفواتير الخاطئة.
* **[تفاصيل ومعاينة الفاتورة والطباعة (Invoice Show & Print)](../pages/invoice-show.md):** المعاينة الشاملة للفاتورة، والطباعة الحرارية المباشرة (80mm) أو A4، والمشاركة عبر واتساب.
* **[نقطة البيع السريعة والكاشير (POS)](../pages/pos.md):** محرك إصدار الفواتير الفوري والسريع للعملاء.
* **[سجل المرتجعات وإشعارات الخصم (Returns)](../pages/returns.md):** متابعة مرتجعات المبيعات والمشتريات وإلغاء الحركات.
* **[تسجيل مرتجع جديد (Create Return)](../pages/create-return.md):** نموذج إنشاء مستند مرتجع مبيعات مرتبط بفاتورة أصلية أو مرتجع حر.
* **[دليل وإدارة العملاء (Customers)](../pages/customers.md):** بطاقات العملاء، حدود الائتمان، تحصيل دفعات السداد، ومتابعة الأرصدة.
* **[كشف حساب وأستاذ العميل (Customer Statement)](../pages/customer-statement.md):** كشف حركة تفصيلي بالمعاملات والمشتريات والدفعات والرصيد التراكمي.

## 4. مصفوفة الصلاحيات والأدوار (Permissions Matrix):
* **الصلاحيات المعتمدة للموديول (`PermissionsSeeder.php`):**
  * `invoices.view`: الاطلاع على قائمة فواتير المبيعات وتفاصيل كل فاتورة.
  * `invoices.create`: إنشاء وإصدار فواتير بيع جديدة.
  * `invoices.edit`: تعديل بيانات الفاتورة (متاح فقط قبل الاعتماد النهائي).
  * `invoices.cancel`: إلغاء الفاتورة الصادرة وعكس المخزون ورصيد العميل.
  * `invoices.delete`: حذف الفواتير إلى سلة المهملات (صلاحية إدارية عليا).
  * `invoices.discount`: منح خصومات مئوية أو مبالغ مقطوعة في الفاتورة.
  * `returns.manage`: إنشاء وإدارة واعتماد مرتجعات المبيعات.
  * `customers.manage`: إضافة وتعديل بيانات العملاء وتحصيل الدفعات.
  * `customers.statement`: استعراض وطباعة كشف حساب وأستاذ العميل.
* **توزيع الصلاحيات على الأدوار الافتراضية:**
  * `admin`: يمتلك كافة صلاحيات المبيعات والعملاء والإلغاء.
  * `cashier`: يمتلك `invoices.view`، `invoices.create`، `returns.manage`، `customers.manage`، `customers.statement`.
  * `accountant`: يمتلك `invoices.view`، `customers.manage`، `customers.statement`، دون صلاحية إلغاء الفواتير إلا بتفويض إداري.

## 5. نطاق الفروع وعزل البيانات (Store Scoping & Guarding):
* ترسل واجهات المبيعات ترويسة `X-Store-Id` مع كل طلب، ويتم مطابقتها في الباك إند عبر `ClientStoreGuard::verified($request)`.
* محاولة قراءة أو إلغاء فاتورة تابعة لفرع آخر غير مصرح للمستخدم به تقابل برفض فوري برمز **HTTP 403** مع كود `store_access_denied`.
* الفلترة برمز `all` محصورة فقط بمن يحمل صلاحية `stores.view_all` أو دور `admin`.

## 6. القواعد المحاسبية والمعمارية الصارمة للمبيعات:
1. **منع الحذف الفيزيائي وحماية التسلسل الضريبي:**
   * الفواتير الملغاة لا تُحذف نهائياً من قاعدة البيانات، بل تتحول حالتها إلى `cancelled` مع الاحتفاظ بالرقم التسلسلي للفاتورة ومطابقة السجلات الضريبية والمحاسبية.
2. **عكس حركة المخزون آلياً (`Stock Reversal`):**
   * عند إلغاء الفاتورة أو إنشاء مرتجع بيع، تُعاد الكميات فوراً إلى رصيد الفرع المسجل به الفاتورة داخل `DB::transaction()` وباستخدام `lockForUpdate()`.
3. **التسوية الفورية لأرصدة العملاء والمديونيات:**
   * إذا كانت الفاتورة آجلة أو مدفوعة جزئياً، يُخصم المبلغ المستحق آلياً من مديونية العميل عبر مكتبة `bcmath`.
4. **الدقة المالية `DECIMAL(12,3)` والتقريب المتماثل:**
   * تُحتسب الضرائب والخصومات وصافي الفواتير عبر كلاس `App\Support\Money\Decimal` مع التقريب المتماثل للنصف للأعلى (`symmetric half-up at 3 dp`).
5. **ارتباط الفواتير بيوم العمل (`Business-Day Cutoff`):**
   * تاريخ ورقم الفاتورة يتبعان يوم عمل المستأجر المحسوب عبر `TenantClock::businessDate()`، مما يضمن دقة الفواتير الصادرة بعد منتصف الليل قبل ساعة القطع.
